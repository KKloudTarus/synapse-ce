# Securibench post-triage evidence

This directory records the local baseline and candidate replay for the pinned
[Securibench Micro](https://github.com/too4words/securibench-micro) revision
`6a5a72488ea830d99f9464fc1f0562c4f864214b`. The scored answer-key digest is
`cdb5a5304703b52bb59ed4a71793ada89c5d89b0e35680dd747cc65b5743ec52`.
The historical scanner was built from Synapse commit
`ad58a4fbd0cb2096f37c2e37e79b7444ec81d230`; CI builds the candidate from its
exact routed source SHA. The private packet salt is a repository Actions secret and
is absent from these artifacts. Packet contexts use canonical CRLF line endings;
the 114-proposal baseline packet was regenerated byte-for-byte from both CRLF and
LF copies of the pinned 125-file corpus.

| Stage | CWE-79 TP | FP | FN | Precision | Recall |
| --- | ---: | ---: | ---: | ---: | ---: |
| Historical post-triage baseline | 78 | 26 | 46 | 0.750 | 0.629 |
| Candidate post-triage replay | 78 | 23 | 46 | 0.772 | 0.629 |

CWE-89 remains TP 5, FP 0, FN 1 in both runs. CWE-78 has zero scored cases in
this corpus and contributes no apparent gain. The local acceptance replay passed
the pinned per-CWE floors, baseline comparison, and newly-lost-true-case check.
The improvement comes from scanner changes after the historical revision:
literal-false branch pruning and conservative literal-local overwrite handling.
It is not attributed to the model.

The model reviewed 114 baseline proposals and 111 candidate proposals. Its raw
response rejected 11 and 10 respectively; the independent syntax proof accepted
zero rejections, so the final verifier retained every proposal. A model-only
decision is diagnostic and cannot suppress a finding without proof.
The candidate's 111 blinded proposals were byte-identical to a subset
of the baseline proposals; their verified raw model exchanges were reused rather
than sampled again. The separate transcripts and audits preserve every decision.

`model-runtime-attestation.json` records the observed GGUF digest, Docker image,
container command, complete mount set, image environment, and loopback binding.
The generator connects directly to loopback without proxies or redirects. This
local observation does not cryptographically prove that each later response came
from the observed process. Each model config binds the record by digest. The files
retain the raw provider exchange, normalized model response, composite audit,
final response, and verdict for each run. The two model configs have identical SHA-256
`8489b4ac40af63cda41b6f321c00dd65b9c5c0ed3ee652bf91267ccb59cb03ca`;
the two composite configs have identical SHA-256
`87a7645554f1ab9ee50be8dbd733daa4057cb5a9e7ff7bcb7dbf729306de6ecc`.
The observed runtime record SHA-256 is
`f23d47981610b45fabc0750197e44a348ed5000b9afbd0efadbe0f618392e9f9`.
The raw baseline and candidate transcript SHA-256 values are
`e30ee06ecfe69a6b47dc9899b194ec0dc69aa59af3461150d78dc07cea337041`
and `c451d5cc4b4d3b18b839ab8b5847bd6c015ea8ffe9d8521539527338c0594fcc`.
The historical report SHA-256 is
`2abf30c9ad35c2a07797df8a65eb230c3c0b18c79b697496845f3fcd30455b0d`.

The workflow regenerates blinded packets and the historical report from pinned
source and corpus revisions, compares the report byte-for-byte, verifies both
retained model/composite artifacts, and runs candidate acceptance. Local
acceptance does not substitute for a green run on the final implementation SHA.
Fork PRs cannot receive the private packet salt, so the hosted post-triage job is
skipped for forks. A green aggregate on a fork does not establish this acceptance.
Same-repository branch writers can alter the workflow or Go test receiving that
secret and are therefore inside its trust boundary.
