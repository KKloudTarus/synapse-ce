# Background ownership inventory

Every piece of background work the API and the worker run, with the role that owns it today and the role that will own it under the production topology of #1559: an **api** tier that serves requests and runs startup barriers, a **control** tier that owns every singleton and every data-only queue kind, and an **execution** tier that claims only the kinds that run a tool.

The table is the source of truth that `docs/docs_background_ownership_drift_test.go` checks against the code:

- every job kind constant in `internal/usecase` and `internal/domain` has a `consumer:<kind>` row whose target owner matches `internal/composition/workerroles`;
- every loop site in `cmd/synapse-api` and `cmd/synapse-worker` (a `go` statement, a `RunOnce` barrier, or a function appended to a maintenance list) carries a `// topology: id=<row>` marker naming a row here, or a `// topology: exempt=<reason>` marker;
- every row names exactly one target owner.

Classes: **consumer** claims a queue kind on every replica; **singleton** runs once per deployment under a lease; **replica loop** runs on every replica by design; **barrier** runs once at startup before the process admits traffic; **lease** is an election, not work; **dev consumer** runs in-process only without a durable queue.

## Reading the gap

A row whose current owner lists the API or more than one profile is a duplicate or a misplaced owner today; the target column is the single owner after the handoff in section 4 of #1559. The `control` and `execution` worker profiles already compose their halves (`internal/composition/workerroles`), and `assertClaimSet` in `cmd/synapse-worker/roles.go` refuses to start a role whose handler map claims another role's kind or leaves an enabled kind unclaimed, and an `execution` role that was given any singleton. The execution role returns before the SIEM export and composes no maintenance task, so it never campaigns for the lease; the control role builds the agent reconciler, the approval sweeper, the accuracy regression and SIEM export from `cmd/synapse-worker/control_singletons.go`, the same builders the `all` profile uses. Moving the API's singletons out is a later deliverable; until then the API rows keep their markers and their current owner.
