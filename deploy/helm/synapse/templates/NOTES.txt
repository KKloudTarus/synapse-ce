Synapse requires pre-existing split Secrets; this chart deliberately never creates Secret data.

The migration hook runs before install and upgrade. API and worker are configured with
SYNAPSE_DB_AUTO_MIGRATE=false and wait for the migration schema state.

Production image references are digest-only. The recommended production posture is
execution.mode=externalNative: the control plane runs here on Kubernetes and the sandboxed execution tier
runs on native EC2/VM hosts. To run the execution tier IN-cluster (execution.mode=inClusterBroker), every
execution node must support unprivileged user namespaces for bubblewrap; standard managed EKS/GKE nodes do
not. A disposable EKS rehearsal proved the control-plane HA, migration, TLS, and fail-closed paths.
